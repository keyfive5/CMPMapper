📋 Common JSON Formats

Format 1: Detector + Method Structure
{
  "$schema": "https://raw.githubusercontent.com/cavi-au/Consent-O-Matic/master/rules.schema.json",
  "SiteName": {
    "detectors": {
      "presentMatcher": {
        "type": "css",
        "target": {
          "selector": ".cookie-banner"
        }
      },
      "showingMatcher": {
        "type": "css", 
        "target": {
          "selector": ".cookie-banner"
        }
      }
}
Format 2: Simple Action Structure
{
  "name": "Example Site",
  "actions": [
    {
      "type": "click",
      "target": {
        "selector": ".accept-button"
      }
    }
  ]
}

🎨 Common Selector Patterns

Banner Detection:
  • .cookie-banner - Class-based banner
  • #cookie-notice - ID-based banner
  • [data-cookie] - Data attribute banner
  • .consent-banner - Consent-specific banner
Button Selection:
  • #accept-cookies - Accept button by ID
  • .accept-button - Accept button by class
  • [data-accept] - Accept button by data attribute
  • button[type="submit"] - Submit button

🔧 Action Types

click - Click an element
hide - Hide an element
wait - Wait for an element
scroll - Scroll to an element

💡 Pro Tips

  • Use data attributes when available - they're more stable than classes
  • Combine multiple selectors with commas for better coverage
  • Test selectors in browser dev tools before using in rules
  • Use displayFilter: true to ensure elements are visible
  • Keep selectors simple and specific for better reliability
